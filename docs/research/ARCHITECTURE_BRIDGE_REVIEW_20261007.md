# Source-bound architecture bridge — verified implementation

Date: 2026-10-07. Scope: bounded local Deep Compose integration, not full-project or scientific release.

## Outcome

The reviewed research can now alter **executable candidate role plans**, not only the research panel or stock choices inside one unchanged plan. Deep Compose retains the original control and, where a reviewed mapping applies, constructs at most two independently solved source-bound alternatives. All alternatives remain unordered.

The bridge contains **10 subtype mappings and 20 explicit comparison options**. It does not convert all 179 subtype cards into recipes. Unsupported mappings remain advisory. Existing Fast Sketch composition behavior remains independent of the bridge, except that unavailable campaign governance and matched unresolved campaign identities now stop generation.

The current research census remains **49 construction dossiers, 179 partial subtype cards, 24 explicit botanical additions, 233 source records, 226 claims, 43 profiles and 25 exact material cards**. The original 275-scope taxonomy plus 24 additions gives 299 tracked scopes. Review states are 168 reviewed-advisory, 64 legacy-advisory and one held source. These counts are not independent experiments, complete botanical knowledge or numerical calibrations.

## Runtime and user interface

- Reuse the exact knowledge context compiled with the request.
- Keep the control, explicit stock anchors, prompt-derived roles, core opening/heart/base coverage, protected recognizers, preserve/avoid constraints and exact quantities.
- Replace only an unprotected optional role, or use spare capacity without violating an exact count or ceiling.
- Solve, critique and report each variant against its own brief.
- Bind executable role-plan signatures separately from physical stock/quantity signatures. Cosmetic labels or role order do not count as architectural diversity.
- Report failed attempts and distinguish a stock alternative from the unchanged control.
- Preserve crystal mass separately from liquid microlitres and preserve the Orris Liquid user hold.
- Show the selected variant's question, roles, timing hypothesis, documentary reference links and holds. A hard-failed critic result is not displayed as an actionable formula.
- Bind adapter and implementation bytes into durable Formula Design fingerprints.
- Use no runtime network calls, new pipeline scripts, physical stock writes or bottle commits.

Use the existing Formula Studio Deep Compose mode; examples include “A peppery freesia perfume,” “A juicy lychee fruit perfume,” or “Lavender incense without Ambroxan.” The control is not a proven winner. A branch may still carry stock, dose-basis or other practical holds.

## Defects caught and corrected during acceptance

1. **Missing campaign governance:** an unreadable hold-bearing manifest previously looked like an empty hold list. Both Fast Sketch and Deep Compose now withhold generation until the governance bytes are available.
2. **Source normalization:** an additional base-card dependency could be discarded when stripping addenda. Only explicitly attached, correctly target-bound addendum bindings are removed; remaining base bindings must match exactly.
3. **Protected role loss:** donor selection now protects both the interpretation's preserve constraints and the accepted brief's protected recognizers, and computes the preservation receipt from actual before/after roles.
4. **Failed-control mislabeling:** a successful later stock alternative is not called the unchanged control when the original failed.
5. **Negation/token mismatch:** raw regex word boundaries treated underscores differently from subtype matching. An explicit “without incense” could reactivate an incense card through a generated title such as `negated_incense`. Exclusion masking now uses the same normalized token space as retrieval. The frozen corpus was not changed to evade the failure.
6. **Variant-specific presentation:** timing/reference metadata and displayed role counts now follow the selected variant rather than the primary candidate.

The first comparison run is retained as [failed initial evidence](architecture_comparison_initial_20261007.json). It found the negation defect. The successful rerun is a separate artifact; historical receipts were not overwritten.
