# Initial all-domain construction library: integrated completion

Date: 6 October 2026.
State: INITIAL_CONSTRUCTION_ADVISORY_INTEGRATION_COMPLETE.

## Outcome

All 49 frozen construction packages now have a retrievable, source-bound initial dossier. The library is integrated into Formula Studio, semantic brief context and goal-directed analysis. Formula Studio exposes architectural options only in the collapsed “Research behind this design” section. Goal analysis adds bounded construction clues after applicable endpoints and user observations; it does not turn source descriptors into automatic dose changes.

This is the completed initial architecture-software coverage layer. It is not a complete empirical perfume model or an exhaustive literature review of every subtype. The initial source-bound core covers 120 overlapping scope entries. The other 155 remain explicitly unreviewed. A single family label, descriptor paragraph or commercial note list does not close those remaining obligations.

Inventory, formulas, stock receipts, comparators, commercial panel registries and the frozen research plan were not rewritten by this work. Existing unrelated worktree changes remain preserved. PW Orris Liquid remains excluded from new compounding. No purchase, physical experiment, addition, safety clearance, release decision, model training or empirical evidence admission occurred.

## What each dossier supplies

- Recognizers and negative space, rather than a generic beauty target.
- Three named functional nodes with exact source entities and source-record hashes. Examples may be chemicals, exact product grades, botanical extracts or documentary references; they are not inventory aliases or executable stock rows.
- Explicitly unmeasured links between functions. Chemical-family similarity does not supply receptor affinities or proof of synergy.
- Two distinct architectural hypotheses, an omission/socket comparison, a question to resolve and stop conditions.
- An explicit partition of initial core facets and unreviewed subtypes.
- Four false action/evidence-authority flags, no calibrated quantities and no concealed neutral or hedonic scores.

Architectural alternatives can be different profiles, not merely equivalent replacements. Natural root-butter iris versus transparent woody-petal iris, for example, must be compared against the actual locked brief. The library cannot protect or unprotect an anchor, impose a recognizer dose floor, or authorize a profile change. Those decisions belong to the request and its applicable evidence.

## Runtime implementation and failure behavior

`engine/formulation_intelligence/construction_library.py` validates a closed schema, exact 49-package membership, subtype partition closure, source bindings, role/architecture references and false authority. It caches parsing by exact library and plan bytes, returns defensive copies and bounds ordinary retrieval to four dossiers.

The existing request-aware knowledge retriever supplies negation-masked positive text. “Lavender without Ambroxan” does not activate the ambergris-type dossier. Generic words such as “smooth and rich” do not activate an unrelated construction family. Request constraints retain precedence.

Missing/malformed library bytes, coverage-plan drift or source/review drift withhold the affected context rather than emitting an empty success. An independent literature claim can remain available when the construction library is unavailable. Withholding one changed source only removes dependent dossiers.

Durable jobs bind the construction module, library, source reviews and frozen coverage plan. Formula-design request identities include the exact construction hash. A changed knowledge file cannot reuse a scientific result solely because a formula name remains the same. No new job type, caller-selected module, pipeline script or live web call was added.

The research options in the UI use textContent rather than HTML interpolation. They remain optional, untested and non-actionable. No extra photos, lots, receipts, density questions or compulsory repeated protocol was added to ordinary personal research.

## Verification and performance boundary

The exact current-source test receipts, hashes, attempt notes and final quick-check state are recorded in `CONSTRUCTION_LIBRARY_COMPLETION_AUDIT_20261006.json`.

The final focused engine suite covers all 49 retrieval paths, negation, closed schemas, protection-floor rejection, source and plan drift, incomplete libraries, endpoint separation, offline deterministic retrieval, Formula Studio propagation, observation precedence and exact request-hash drift. Focused backend checks cover job fingerprints, UI/API context and durable job contracts.

A parallel quick-check attempt exposed a pre-existing shared SQLite test database: one pytest process could drop another process’s tables. The backend fixture now owns a database under each test’s unique tmp_path. A focused regression closes one fixture and verifies the other still contains lab_engine_jobs. The failed attempt artifact is preserved; it is not relabeled as a pass. This repair changes test infrastructure only, not the live DB or production scientific gates.

The final offline retrieval benchmark uses 49 distinct package prompts and 490 timed warm calls. p50 was 33.00 ms, p95 63.01 ms and maximum 120.20 ms during concurrent verification. All repeated outputs matched and four-thread results equaled serial results. This establishes retrieval overhead below the 500 ms budget in this test, not a new full-formula, 368-formula, memory, cold-start or sensory benchmark.

Scoped engine/backend Ruff and mypy checks and JavaScript syntax validation are included. The quick project verifier remains partial and cannot establish merge/release readiness. No full verifier, Docker build, migration cycle or full backend suite was claimed for this knowledge-only integration.
