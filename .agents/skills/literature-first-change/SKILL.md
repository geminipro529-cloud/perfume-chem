# Literature-First Change

1. Read the governing plan, `AGENTS.md`, affected contracts, call sites, and tests.
2. State the system boundary, intended behavior, uncertainty, and cheapest viable implementation.
3. Search local references first. Use current primary literature for scientific claims and official docs for technical APIs.
4. Reuse a fresh source cache when the question and source revision are unchanged.
5. Separate authoritative facts, literature-derived assumptions, heuristics, and unknowns.
6. Write a concise implementation plan before editing, then proceed under the user's standing approval.
7. Patch narrowly, preserve unrelated changes, and finish through the verification ladder.
